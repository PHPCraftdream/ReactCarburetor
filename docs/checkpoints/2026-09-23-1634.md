## Decisions

- **D2/oxc_semantic is used minimally, by explicit owner instruction** — capture/binding resolution
  and same-file heritage-chain walking only; no type-checking, no cross-file resolution. This is the
  first dependency this crate has added beyond the `oxc_parser`/`oxc_ast` family, and LA-1's prompt
  explicitly tells the sub-agent to verify the real 0.150.0 API from the downloaded source rather
  than trust any assumed shape (confirmed reachable via `cargo add --dry-run` this session; the
  actual crate source was not inspected by the orchestrator, only resolved as available).
- **D1 removes the public/private split entirely for R2** — extractability, not visibility, is the
  boundary; the only remaining exclusions are things that are mechanically or contractually
  impossible to move regardless of body content (lifecycle names, the framework's own override
  points, decorators, `implements`, etc.).
- **D6 narrows scope to component classes only, explicitly dropping store classes** from both new
  rules' territory — a real reduction from the plan's original recommendation, and worth
  remembering if a future round ever revisits "should stores get this treatment too."
- **A new Cargo dependency requires the same explicit-approval discipline as a version bump** — D2
  was surfaced to the user as a real question rather than decided unilaterally, consistent with the
  standing "never raise a version without explicit permission" rule being read as covering "never
  add a new dependency" too.

## Decisions

- **#72/#73 formally dropped, not deferred further**: the benchmark (#69) already showed proxy
  allocation isn't material, and #91's own real fix (`getEntry`'s view cache) was the audit's
  actual #1 finding all along — building a cross-render proxy cache for `useCarburetor` on top of
  that would be solving a problem the numbers say doesn't exist.
- **`connectDevTools`'s full-state re-clone and the transaction write-set double-copy (audit
  findings #2/#3) deliberately left unfixed**, per the audit's own priority ranking: real but
  lower-impact, and the transaction copy explicitly belongs bundled with other transaction work,
  never as a standalone fix.
- **A rush usage-limit that names a multi-hour reset time is treated as a hard quota, not a
  situational 429**: revert the task to `pending` with a note, do not retry blindly, do not keep
  attempting new launches — this is the same distinction rush.md draws for the shorter 429 case
  earlier in the session, generalized to the longer window seen here.
- **`connect()`'s design, settled through live iteration with the user**: no explicit field list
  (automatic per-render tracking instead, matching `useCarburetor`'s own precision); types inferred
  from the store's generic parameter alone (`TReadonly<T>`, reusing the exact type `read()` already
  returns) with no `as const`/manual type parameter; `source` accepts a carburetor directly or a
  function resolving one, so a prop swap re-points the connection.
- **`connect()` implemented directly, not delegated**: the design-reasoning chain (persistent-proxy
  rebuild-on-target-change, lazy generation-based reads reset, the double-forceUpdate trap avoided
  by capturing the version freshly on every actual read rather than once per commit) was involved
  enough that writing an equivalent delegation prompt would have meant transcribing the same
  reasoning anyway.
- **Small, mechanical gaps found during review keep getting fixed on the spot rather than
  re-delegated** — this session's instance: `requireTsdoc.mts`'s `paramName()` unwrap bug, found
  independently re-verifying #89, fixed with its own regression test, in the same turn.

## Session summary

The user owns React Carburetor (https://github.com/PHPCraftdream/ReactCarburetor), a state
engine whose thesis is that state lives outside the React tree and class components subscribe
to exactly the fields they read, so no hooks, no dependency arrays and no auto-memoizing
compiler are needed. This session cloned the 2019-era repository into `D:\dev\ReactCarburetor`,
migrated its whole toolchain (Rslib + tsgo, Rstest, oxlint with type-aware rules, TypeScript 7,
React 19, Rsbuild + Tailwind 4 for the demo), then rebuilt the engine itself: path-precise
invalidation through read/write tracking proxies, per-carburetor update scheduling (immediate by
default, `ComponentUpdateThrottle` opt-in for streaming sources), `computed`, `transaction`,
`ResourceCarburetor` with Suspense support, per-request scopes, and tooling (devtools, persist,
history, `waitForUpdate`) plus an opt-in hooks bridge at `react-carburetor/interop`.

The repository was re-created as a single squash commit under the user's current identity
(`Marat K <phpcraftdream@gmail.com>`), published publicly, and three commits are pushed with
green CI: `0d412c4` (initial), `b800f44` (computed/transactions/resources/scopes/tooling),

## Decisions

- Stay class-first: no hooks, no function components, and no reliance on React Compiler in the
  public API. The user rejected a hooks-first core explicitly; the hooks bridge was accepted only
  as a separate opt-in entry point (`react-carburetor/interop`).
- Deliver precise invalidation rather than time-based smoothing: immediate delivery by default and
  `ComponentUpdateThrottle` only for streaming sources, instead of the original global 40 ms
  throttle that taxed every click.
- Traversal is not a read: reaching into `data.items` on the way to a leaf does not subscribe to
  the container, otherwise every row would depend on the whole list. Enumeration (`Object.keys`)
  and `in` checks do subscribe.
- Write lint rules as one ESLint-compatible plugin rather than an oxlint-native one: oxlint's JS
  plugin API (alpha since 2026-03-11) is ESLint-identical, so a single implementation runs in both
  oxlint (`jsPlugins`) and ESLint v9 flat config, and `RuleTester` provides the rule tests.
- Extend the existing TaskList with the lint plan instead of replacing it, so the remaining review
  tasks (#33–#37) finish first — ordering is carried by id, not by artificial `blockedBy` chains.

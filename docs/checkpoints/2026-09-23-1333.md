## Decisions

- **A sub-agent's own internal "verdict: accepted/PASS" narration is evidence of nothing** — every
  merge decision this session was made from the orchestrator's own independent diff read, build/
  typecheck/lint/`check:layout`/test run, and revert-proof, never from trusting a rush session's
  self-review text (even when, as in round 3's R3-06+07+08, that self-review would have missed the
  actual gap).
- **A rush-session timeout is not automatically a failure** — before assuming lost work and
  resuming, always check the worktree's own `git log`/`git status` first; twice this session
  (round 3's R2-07+08+09+12-successor bundle, and round 5's R5-04+06+08) the actual code fix was
  already safely committed before the timeout fired, and treating the timeout as "start over" would
  have thrown away real, verified work.
- **A flaky test gets root-caused and fixed in the same turn it's noticed, in its own commit** —
  the ResourceCache TTL test's real-clock race was fixed immediately via fake timers rather than
  deferred, and kept as a separate commit from whatever round-5 task happened to be in flight when
  it surfaced, since the fix wasn't actually part of that finding's scope.
- **`engines.node` metadata corrections vs. version bumps are treated as genuinely different
  things** — round 5's R5-04 (AbortController requiring Node 14.17+, but `engines.node` claiming
  14.6.0) was resolved via runtime feature-detection specifically so the ALREADY-advertised floor
  could stay literally true, rather than "fixing" the mismatch by raising the advertised minimum —
  the standing "never raise a version without explicit permission" rule was treated as covering
  metadata bumps too, not just dependency upgrades.

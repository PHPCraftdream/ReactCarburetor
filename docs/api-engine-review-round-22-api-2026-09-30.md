## R22-API-01 — restore partly mutates a valid snapshot before a locked nested property throws (P2)

**Supported contract and mechanism.** `README.md:896-904` defines plain state as own enumerable string-keyed data; `Store/Tracking/Aliases/AliasLedger.ts:32-51,122-139` accepts data descriptors regardless of `writable`/`configurable`. `README.md:681-683` promises that restore checks affected readonly changes *before* draft mutation and falls back to root replacement when needed; `Store/Carburetor.ts:190-192,206-242` exposes snapshot and restore, and `Store/Utils/deepClone.ts:48-65` deliberately makes snapshot's ordinary plain fields writable. A read of an object behind a frozen/locked property is separately documented as outside **tracked read** guarantees (`README.md:695-703`); this reproduction does **not** use a tracked read of that property. Its constructor, snapshot and direct `setData` accept the state and the changed snapshot.

`Store/Paths/Diff/applyDiff.ts:70-117` preflights writable restrictions for a *replacement* scalar or kind change, but for a same-kind nested object it recurses (`:102-109`) without testing whether `previous.row` is simultaneously **non-writable and non-configurable**. `:139-158` then applies the earlier `other` write before `:51-57` evaluates `target.row`. The write proxy's `get` trap wraps the raw object (`Store/Tracking/createWriteProxy.ts:293-309`); JavaScript's proxy invariant prohibits returning that wrapper for a non-configurable, non-writable data property. This throws **after** the sibling draft write, and `Store/Carburetor.ts:229-241` never reaches `emitUpdate`. The live raw object has changed although the version and subscribers have not. The existing `applyDiff` false → `setData(deepClone(data))` fallback at `Carburetor.ts:235-239` would have installed both values had the preflight rejected this unwrappable nested branch.

**Actual public reproduction**, Node 24.12.0 against this tree's copied built CJS, independently reproduced with Bun 1.4.2 importing this tree's actual TS barrel and with Node's copied `--conditions=production` CJS:

```js
const {Carburetor} = require('react-carburetor');
const data = {other: 0};
Object.defineProperty(data, 'row', {
  value: {n: 1}, writable: false, configurable: false, enumerable: true
});
const store = new Carburetor(data);
const saved = store.snapshot();
saved.other = 4;
saved.row.n = 2;
const heard = [];
store.watch(d => d.other, value => heard.push(value));
try { store.restore(saved); } catch (error) { console.log(error.name); }
console.log(store.getData(), store.getVersion(), heard);
```

Node built development: `TypeError`; live `{other:4,row:{n:1}}`, version `0`, `heard=[]`. The next microtask still had that same unpublished state and emitted the unpublished-draft development diagnostic. Bun source also threw a proxy-invariant `TypeError`, leaving `row.n=1` and version `0`; built production independently threw `TypeError` with `other=4`, `row.n=1`, version `0` (no development-only guard). A separate fresh-store control calling **`setData(saved)`** instead completed with `other=4`, `row.n=2`, version `1` and watcher `[4]`, demonstrating an implementable supported value change. A separate history control replacing such a root through `setData` undid to `other=0,row.n=1` with the original `row.writable=false` and redid to `other=4,row.n=2`; this is a failure of the public ordinary restore path, not a claim that history's owned replay loses its lock.

**Expected / remedy.** `restore(saved)` should either install both changed values and notify the interested readers, or reject before changing any live value if an input really is invalid; this input is already accepted by the documented state model. During the existing all-branch preflight, when a same-kind nested branch must be changed but its containing own property is non-configurable **and** non-writable, choose the detached root-replacement fallback instead of descending through the draft proxy. Preserve the preflight-before-first-write invariant across siblings; avoid changing proxy traps to violate JS invariants or swallowing the throw. The ordinary snapshot's normalized descriptor remains intentionally writable after fallback; history's owned replay is a distinct contract.

## Settled metadata-only descriptor contract — not counted

A replacement that changes **only** the `writable` or `configurable` metadata of an otherwise equal ordinary-object enumerable property is **not** promised to notify: `README.md:896-904` defines plain state through `Object.keys` data keys/values, `Store/Utils/deepClone.ts:48-65` normalizes flags, and `Models/Store.ts:5-11,101-110` explicitly says descriptor introspection does not register a value dependency. `Component/Connection/sameSelection.ts` can compare descriptors once a selector actually runs, but that does not extend publication to an ordinary metadata-only `setData`. The previously withdrawn R21-API-01 observation was therefore not recycled here. R22-API-01 changes two *data values* in an accepted snapshot; the locked descriptor merely explains why its draft install cannot occur in place.

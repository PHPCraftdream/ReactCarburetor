## R23-ENG-01 — a newly restrictive branch loses its descriptor on history redo (P2)

**Contract.** `README.md:656-685,921-930` promises owned history endpoints retaining supported readonly descriptors through undo/redo, while ordinary `snapshot()` normalizes plain-property flags and ordinary descriptor-only changes are not state notifications. A valid `update` may replace a writable plain branch with an object whose *enumerable own data field* is readonly. The field's value actually changes, making this an undoable operation. Its readonly status governs whether a subsequent draft write succeeds.

**Supported source repro**, using only public `Carburetor`, `CarburetorHistory` and `diagnostics` exports:

```ts
import {Carburetor, CarburetorHistory, diagnostics} from './lib/src/Carburetor/index.ts';
diagnostics.setEnabled(false);
class S extends Carburetor<{row: {x: number}}> {
    edit(change: (draft: {row: {x: number}}) => void) { this.update(change); }
}
const s = new S({row: {x: 1}});
const h = new CarburetorHistory(s);
const next = {x: 2};
Object.defineProperty(next, 'x', {
    value: 2, writable: false, enumerable: true, configurable: true,
});
s.edit(d => { d.row = next; });
const before = Object.getOwnPropertyDescriptor(s.getData().row, 'x')!.writable;
h.undo();
h.redo();
const after = Object.getOwnPropertyDescriptor(s.getData().row, 'x')!.writable;
console.log({before, after, value: s.getData().row.x, canUndo: h.canUndo()});
```

**Actual Bun source:** `before:false, after:true, value:2, canUndo:true`; **expected:** `before:false, after:false, value:2, canUndo:true`. The value round-trips but the owned readonly endpoint does not. A second bounded source consumer verified the consequence: `s.edit(d => { d.row.x = 3; })` threw `TypeError` before undo/redo but was **accepted** after redo, writing `3`. Independently, adding a *new* `row` containing a non-writable, non-configurable enumerable `x` yielded descriptor flags `[false,false]` immediately after `update`, then `[true,true]` after undo/redo. **Copied runtime confirmation:** Node, with a CJS `Carburetor` and ESM `CarburetorHistory`, reproduced `before:false, after:true, canUndo:true, canRedo:false`; its expected mixed-format duplicate-module diagnostics also appeared and were not treated as a failure.

**Mechanism.** `Store/Tracking/createWriteProxy.ts:296-306` diffs same-kind replaced branches into scalar leaf patches; `Store/Paths/Diff/diffPaths.ts:85-110,114-143` walks enumerable values but does not signal that a *newly supplied* field became restrictive. `Tooling/CarburetorHistory.ts:265-268` accepts a primitive patch without ownership/classification; for an object patch `:279-296` observes `lockedArray` but ignores the `restricted` trait reported by `Tooling/Graph/ownHistoryGraph.ts:64-75`. Since the *prior* baseline is unrestricted, `CarburetorHistory.ts:385-409` may admit these patches via the scalar fast path or its permissive object preflight. `Store/Paths/Diff/installPatch.ts:30-41` assigns/deep-clones patch values rather than preserving newly restricted descriptors, so redo reconstructs a writable endpoint. `Tooling/Graph/canInstallOwnedPatch.ts:12-51` correctly checks whether a patch can write to an *existing* restricted baseline, but cannot discover a restriction discarded while advancing an unrestricted one. This is separate from the round-22 case, which started with a readonly baseline and was repaired.

**Remedy.** For a value-changing branch replacement or addition, recognize newly restrictive enumerable own data descriptors in the changed endpoint, including the scalar-leaf diff case, before admitting a patch representation that normalizes them. Use privately owned complete endpoints/owned replay where needed; maintain the ordinary scalar patch fast path and do not turn descriptor-only metadata into a new notification. Carry restriction classification forward when admitting object payloads. Ensure subsequent updates and independent histories retain the chosen endpoint. **Limit:** this report proves the two specific supported shapes above, not every possible restriction/graph topology or an exhaustive configuration matrix.

## R15-API-01 — P2 — Same-message replacement retains an unrelated raw request failure

**Public contract and precise mechanism.** `Carburetor.setData(data)` replaces the whole state and synchronously publishes its diff (`lib/src/Carburetor/Store/Carburetor.ts:150-186,558-596`). The public subclass `ResourceCarburetor` stores a loader's actual rejection beside its serializable Error message (`lib/src/Carburetor/Resource/ResourceCarburetor.ts:449-467`), and `suspend(args)` preferentially throws that raw rejection for the settled key (`:215-233`). Its `didSetData` runs `reconcileError` before publication (`:171-199`), but the latter retains the raw rejection whenever `hasLastError` is true and `lastErrorMessage === state.error` (`:188-193`). A **new, whole-state Error answer** with a new `updatedAt` and the *same message* therefore retains the rejection from a different, earlier request. That rejected object may contain privileged request metadata, a custom code, or an obsolete cause even when the public wire message is intentionally unchanged. A subscriber, error boundary or external `getLastError()` reader receives the old cause despite observing the newly published wire answer. This is the still-open same-message case of the R14 single-slot replacement fix, not the previously repaired changed-message case.

**Deterministic actual-source reproduction.** Load key `'a'` from a loader rejecting `Object.assign(new Error('denied'), {code:'RAW_ORIGINAL'})`. Register a synchronous public `subscribe` callback reading `serialize()`, `getLastError()` and the actual value thrown by `suspend('a')`; invoke `resource.setData({...resource.getData(), status:EResourceStatus.Error, error:'denied', updatedAt:resource.getData().updatedAt + 1})`. Bun 1.4.2 printed `{"wire":"{\"status\":\"error\",\"error\":\"denied\",\"updatedAt\":1790742144324,\"key\":\"\\\"a\\\"\"}","raw":true,"suspend":true}`: the subscriber fired for the new timestamp and both raw APIs still returned exactly the former rejection. A second source run confirmed `getLastError() === old`, `suspend('a') === old` and `.code === 'SECRET'` after the replacement. The changed message is not a necessary trigger: the *answer ownership* changed although its error description did not.

**Relevant controls and boundary.** `setData(resource.getData())` with exactly the identical state object retained the current raw rejection; a subclass's `update` of **only** `updatedAt` also retained it; those do not replace the Error answer and must not be conflated with a wholesale adoption of a different state object. `restore({...snapshot,error:'denied'})` reconstructed a same-message Error instead of keeping the old raw object, as the existing restore contract specifies (`ResourceCarburetor.ts:109-159`). A keyed-cache `setData` adopting a *different entry object* with the same message and new timestamp cleared `getFailure('a')` and made `suspend('a')` throw a fresh same-message Error, not its former raw rejection (`ResourceCache.ts:80-106`). The discrepancy is specific to single-slot wholesale replacement, not an assertion that unrelated draft metadata changes must destroy the loader's provenance.

**Acceptance for fix owner.** Reconcile raw failure ownership on a distinct public whole-state Error replacement before synchronous patch listeners/subscribers are invoked, even if `status`/`error` text are unchanged; preserve the actual raw rejection on an untouched current request settlement and on an unrelated `draft`/`update` field write, preserve exact same-object no-op behavior where appropriate, and do not fabricate a settled key out of keyless `IResourceData`. Cover same-message and changed-message Error replacements, Error→Success, restore/fromJSON controls, `getLastError`, `suspend` throw identity, wire `snapshot`/`serialize` and a synchronous subscriber. No product source was changed in this review.

## R14-MODULE-01 — P2 — Cross-format selection cannot canonicalize an engine-created read proxy

**Contract interpretation, without assuming either blanket support or a blanket exclusion.** `CHANGELOG.md:447-456` explicitly names both duplicated installs and loading the same install through CJS and ESM; it says the context, update batch, update wave, UID and token-name registry were shared across **every copy** to prevent real cross-copy consumer failures. `docs/react-compatibility.md:34-58` expands this: a provider from one copy must serve a scoped component from the other, transactions span stores from any copy, and computed invalidation/settlement is shared. Its line 57-58 says the *per-object tracking WeakMaps* are intentionally not shared, because they are “always reached through the one copy that owns the data object.” The following development message recommends deduplication or one module format (`:64-76`); it is a diagnostic/recommendation, not an explicit statement that the supported cross-copy operations above become undefined whenever it fires. `scripts/consumer-matrix/duplicateCheck.mjs:9-66` checks the diagnostic on an actual dual-format packed install; it does **not** exercise a store created by one format through a component from the other. Conversely, these sources do not promise that *every* arbitrary cross-version/runtime-internal object may be passed between copies. The observed consumer uses a store's documented `ICarburetor.read` surface (`Models/Store.ts:81-89`), not an externally forged proxy.

**Causal mechanism in this freeze.** A CJS `Carburetor.read(record)` creates tracked proxies in CJS `createReadProxy.ts:420-429`, and registers their proxy→raw-target identity through *its own* `liveViews.noteReadTarget` (`Store/Tracking/liveViews.ts:13-38`). An ESM `AntiHookComponent.connectSelection` invokes that CJS source's `read()` but calls *its own ESM* `detachSelection()` (`Component/AntiHookComponent/Reads.tsx:157-180`; `Connection/detachSelection.ts:20-30`). The ESM `detachOpaque` consults its separate module-local `liveViews.readTarget(proxy)` (`Store/Utils/Selection/detachOpaque.ts:48-74`), so it cannot recognize the CJS-created proxy. When the selector includes both a tracked plain key and a raw Map holding the *same underlying object* as its key, the copier's `seen` map is indexed once under the read-proxy identity and once under the raw object identity. It makes two independent copies (`detachOpaque.ts:86-95,155-174`). The resulting selection's `index.get(selection.key)` is `undefined` and its Map key is not `selection.key`. Same-format copies share one local registry and do not take this path. `docs/react-compatibility.md:57-58`'s “always reached through one copy” premise does not hold when the component's selection/detachment implementation is from the other copy.

**Observed failure, attributed to integration owner (not independently rerun).** In an actual built CJS-store → ESM-`AntiHookComponent.connectSelection` consumer, the integration owner observed `lookup:undefined, same:false` for the plain-object/Map-key alias and development deduplication warnings for four shared globals. Expected in the connected child's detached selection: the Map entry remains accessible through the selected key (`lookup:'answer', same:true`, given the owner's original `answer` entry); that alias is a functional graph invariant, not a claim that looking up the *original un-copied* key in a copied Map must work. The source trace above independently identifies why this failure is specific to the cross-copy boundary. This reviewer did **not** rerun the reported built-output scenario or claim to have exercised a packed dual-format consumer; local source-only analysis is not an additional runtime reproduction.

**Acceptance.** Preserve canonical proxy/raw-target identity when a supported `ICarburetor` source and a consumer hook/class selection come from two copies/module formats, in **both** graph traversal orders (plain key first and raw Map first), and retain precise read tracking, detached mutation isolation and the legitimate duplicate-copy diagnostic. Check class `connectSelection` and the hook's common detachment consumer (`Interop/useCarburetorValue.ts:86-98,229-249`) against the actual shipped CJS/ESM combination, plus ordinary same-format controls. Use a trusted engine-owned identity mechanism; do not infer provenance of arbitrary third-party Proxy objects by duck typing, and do not invent cross-version ABI guarantees. Explicitly reconcile the per-copy WeakMap statement in `docs/react-compatibility.md:57-58` with the supported cross-copy graph use case. No timing, allocation or full multi-install compatibility claim is made.

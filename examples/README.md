# Documentation examples and native lint rules

Runnable examples live in `examples/`, separately from prose and generated output. Add TypeScript or TSX source there, import public APIs through `@react-carburetor/core`, `@react-carburetor/core/interop`, or `@react-carburetor/core/lint`, and keep each directory to seven entries. `examples/tsconfig.json` checks the proper examples as a consumer against repository sources; it does not emit files.

Every `ts`/`tsx`/`js`/`jsx` block in README and docs Markdown is generated from an `examples/` source file with an `<!-- example:file examples/path/File.tsx -->` marker; a `#name` suffix copies a named `// #region name` excerpt. `npm run docs:build` copies sources into the fences and `npm run docs:check` verifies the generated output is current and rejects any unmarked code block. Keep examples self-contained and meaningful rather than listing names solely for coverage.

`examples/wrong/` is deliberately excluded from the positive typecheck and lint pass. Directories under `examples/wrong/` that start with `_` are the exception: `_unlinted/<hazard-id>/` holds wrong examples for hazards the native linter does not catch at all (a rule that is off by default, not yet implemented, or not a rule), so their files must produce zero findings and are typechecked like proper examples through `scripts/tools/tsconfig.examples-unlinted.json`. Its snippets demonstrate individual bad practices and are checked by `__tests__/Native/examples.test.ts`; each must produce exactly its named rule diagnostic and no unrelated findings. A file named `Name.expected.<rule>[.x<N>].<rule2>.tsx` declares a hazard that by nature raises several findings: each listed rule once, or N times with `.x<N>`; the test compares the exact multiset. Do not suppress a rule in a proper example or disable allocation rules for the examples tree. Internal source-style checks for TSDoc and parent imports are not consumer-facing and have a limited examples-only override.

Run `npm run docs:build` after changing source regions; `npm run docs:check` checks the generated documentation, and examples are typechecked by `npm run typecheck` and linted by the native linter. The examples test is run with `node node_modules/@rstest/core/bin/rstest.js run __tests__/Native/examples.test.ts __tests__/Tooling/examples`.

The examples are an ongoing API guide, not a bulk migration of the existing documentation. Add or update a focused example when a public API needs practical coverage; the export-coverage suite verifies current public names occur in real marked examples.
